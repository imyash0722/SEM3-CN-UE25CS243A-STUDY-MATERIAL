An IP router with a Maximum Transmission Unit (MTU) of
200 bytes has received an IP packet of size 520 bytes with
an IP header of length 20 bytes. The values of the relevant
fields in the IP header.

The Fragment Offset field
is measured in units of 8
bytes. This means the
amount of data in every
fragment (except the
last) must be a multiple
of 8 — otherwise the
offset of the next
fragment wouldn't land
on a whole number.

180 is not a multiple of 8
(180 + 8 = 22.5). So we
can't actually use the full
180 bytes per fragment —
we must round down to
the nearest multiple of 8.
So we choose 22 not 23.

Why fragmentation is avoided

= One lost fragment loses them all
IP never resends. If one fragment is missing, the destination throws away the rest.

= TCP sizes its segments to fit
1,500 - 20 (IP) - 20 (TCP) = 1,460 bytes of data, so IP never needs to split.

= Senders ask routers not to split
The DF bit is set. A router that can't forward the packet drops it and replies with the MTU it needs.

= IPV6 routers never fragment
Only the sender may split an IPv6 packet. Routers just drop it and report back.

Result: the sender learns the smallest MTU on the whole path and never sends anything bigger. This is called path
MTU discovery, and it is why routers today almost never fragment.
