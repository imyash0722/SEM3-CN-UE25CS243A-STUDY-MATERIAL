What is Data Center Networking?
* Connects servers, storage, applications, virtual machines, and external networks.

* Designed for high bandwidth, low latency, reliability, scalability, and security.
* Modern data centers increasingly handle large volumes of server-to-server (east-west)
traffic.

Types of Data Center Traffic:

North-South traffic

User - Internet -> Data Center - Server

Traffic entering or leaving the data center. Example: User accessing a web application.
East-West traffic

Server A © Server B < Database < Storage

Traffic between resources inside the data center.

Very important for distributed applications, cloud platforms, microservices, and Al
workloads.

Traditional 3-Tier Architecture (also known as the hierarchical network design)
was the gold standard for enterprise and early data center networks for
decades.

It uses a top-down, rigid structure designed to manage data traveling between
the internal network and the outside world.

Access layer = connects servers.

Aggregation layer - combines access switches.

Core layer - provides high-speed connectivity.

Limitation: hierarchical design can create bottlenecks and blocked/suboptimal
paths, particularly for heavy east-west traffic

* Aleaf-spine network is a modern data-center architecture designed to provide
high bandwidth, low and predictable latency, redundancy, and scalable server-
to-server communication.

* Itis based on a Clos topology (multi-stage network architecture).
* Leaf switches - sits at the top of each server rack
* Connect directly to servers, storage systems, firewalls, load balancers, etc.
¢ Usually act as Top-of-Rack (ToR) switches.
* Every leaf connects to every spine.
* Leaf switches generally do not connect directly to other leaf switches.

* Spine switches

* Form the high-speed backbone of the data-center fabric.

* Every spine connects to every leaf.

* They provide paths between different leaf switches.

* They normally do not directly connect to servers, connect only to leaf switches

Every switch routes

Leaf A sees four routes to leaf B, all the same length. None is
switched off, unlike spanning tree.

Hash the flow, not the packet

It computes a hash of the flow’s source and destination addresses,
ports and protocol, and uses it to pick one of the four.

Same flow, same path

Every packet of flow X takes spine 2, so none overtake each other.
Flow Y hashes to spine 4.

A spine fails?
Leaf A drops it from the set and re-hashes onto the other three.
Traffic moves in milliseconds.

Why not per packet? Packets on different paths arrive out of order; TCP reads that as loss and halves its window. Per-flow

hashing avoids it.

Putting it together: the life of one request
Your phone sends a request to the service’s one public address north-south
Border router brings it into the datacenter north-south

Load balancer owns that public address and picks a front-end server that is not busy

Front-end server asks dozens of internal services: cart, prices, stock, recommendations east-west

Leaf—spine + ECMP carry every internal request, each flow hashed onto one path

Answers return the front end builds the page; the load balancer sends it back to you north-south

One click, two kinds of traffic: one request in and one page out (north—south), and dozens of requests between servers in
the middle (east-west). Every design choice in this topic serves steps 4 and 5.
