SLIDE 13: The Internet: A "Nuts and Bolts" View (Overview)
================================================================================

COMPUTER NETWORKS: The Internet – Nuts & Bolts View

1. End Systems (Hosts):
   • Billions of connected computing devices.
   • Hosts = End systems running network applications at the Internet's "edge" (clients & servers).
2. Packet Switches:
   • Forward packets (chunks of data) across the network.
   • Main types: Routers (typically used in network core) and Link-layer Switches (typically used in access networks).
3. Communication Links:
   • Physical media: Fiber optics, Copper wire, Coaxial cable, Radio spectrum, Satellite.
   • Transmission rate = Link Bandwidth (measured in bits per second, bps).
4. Networks:
   • A collection of connected devices, routers, and links managed by an organization (e.g., Enterprise network, Home network, Mobile network, Content provider network, Data center network).

Network Protocols:
• Communication between machines/computers (devices) rather than humans.

SLIDE 27: Physical Media: Guided vs. Unguided & Twisted Pair
================================================================================

COMPUTER NETWORKS: Physical Media Fundamentals

Concepts:
• Bit: The physical unit of data that propagates between transmitter/receiver pairs.
• Physical Link: The transmission medium that lies between transmitter and receiver.
• Guided Media:
  - Waves are guided along a solid physical medium: Copper wire, Optical fiber, Coaxial cable.
• Unguided Media:
  - Waves propagate freely through the atmosphere or outer space without physical guides: Wireless radio, microwave, satellite.

Twisted Pair (TP) Copper Wire:
• Two insulated copper wires arranged in a regular spiral pattern to reduce electromagnetic interference (crosstalk).
• Types:
  - UTP: Unshielded Twisted Pair (most common for LAN cabling).
  - STP: Shielded Twisted Pair (has extra foil shielding for noisy environments).
• Standard Categories:
  - Category 5 (Cat 5): 100 Mbps, 1 Gbps Ethernet (100m distance).
  - Category 6 (Cat 6): 10 Gbps Ethernet.

================================================================================
SLIDE 28: Physical Media: Coaxial Cable and Fiber Optics
================================================================================

COMPUTER NETWORKS: Coaxial Cable vs. Optical Fiber

1. Coaxial Cable:
   • Construction: Two concentric copper conductors (central inner core and outer braided shielding), concentric rather than parallel.
   • Characteristics: Bidirectional transmission.
   • Broadband: Can carry multiple frequency channels simultaneously via Frequency Division Multiplexing (FDM); 100s of Mbps per channel.
   • Common Use: Cable TV and Cable Internet (DOCSIS).

2. Fiber Optic Cable:
   • Construction: Thin, flexible glass fiber carrying pulses of light, where each pulse represents a bit.
   • High-Speed Operation: Point-to-point transmission rates of 10s to 100s of Gbps.
   • Low Error Rate / High Quality:
     - Repeaters spaced far apart (tens to hundreds of kilometers).
     - Immune to electromagnetic interference (EMI) and radio frequency noise.
     - Very low attenuation compared to copper over long distances.

SLIDE 29: Physical Media: Wireless Radio & Link Duplex Modes
================================================================================

COMPUTER NETWORKS: Wireless Radio Links & Transmission Modes

Wireless Radio Characteristics:
• Signal carried in electromagnetic spectrum without physical wire.
• Broadcast medium; signals are susceptible to:
  - Reflection: Signals bounce off walls and terrain.
  - Obstruction: Objects block direct path.
  - Interference: Multiple devices transmitting on same/neighboring frequencies.

Radio Link Types:
1. Terrestrial Microwave: Point-to-point directional dishes, up to 45 Mbps channels.
2. Wireless LAN (WiFi): Shared local coverage, up to 100s of Mbps.
3. Wide-Area Cellular: 4G/5G mobile links, 10s to 100s of Mbps.
4. Satellite:
   • Up to 45 Mbps per channel.
   • Geosynchronous (GEO): ~36,000 km altitude, ~280 ms one-way propagation delay.
   • Low Earth Orbit (LEO): ~500-1200 km altitude (e.g., Starlink), much lower latency.

Duplex Transmission Modes:
• Half-Duplex:
  - Data can only be transmitted in ONE direction at a time.
  - Sender and receiver take turns using a single communication channel (e.g., Walkie-talkie, traditional WiFi).
• Full-Duplex:
  - Data can be transmitted and received SIMULTANEOUSLY in both directions.
  - Uses two separate physical channels (or frequency division), one for sending and one for receiving (e.g., Telephone call, Full-duplex Ethernet).

SLIDE 30: Network Core: Fundamentals
================================================================================

COMPUTER NETWORKS: Network Core

• Mesh of Interconnected Routers: The network core is a mesh of switches and routers that interconnect access networks across the globe.
• Packet-Switching Principle:
  - Hosts break application-layer messages into smaller chunks called PACKETS.
  - Packets are forwarded from one router to the next across communication links on the path from source to destination.
  - Each packet is transmitted across each communication link at the FULL link capacity (transmission rate).

SLIDE 31: Hosts: Sending Packets of Data
================================================================================

COMPUTER NETWORKS: Host Packet Transmission

Host-Sending Function:
• Takes an application message of arbitrary length.
• Breaks application messages into chunks of size L bits (packets).
• Transmits packet into access network at transmission rate R:
  - Link transmission rate, also called link capacity, link bandwidth.

Packet Transmission Delay:
• Time needed to transmit (push out) an L-bit packet into a link with transmission rate R bits/sec:
  
                 L (bits)
  d_trans  =  -------------   (seconds)
                 R (bits/sec)

Example:
  Packet size L = 10,000 bits
  Transmission rate R = 100 Mbps (10^8 bps)
  d_trans = 10,000 / 100,000,000 = 0.0001 seconds = 0.1 ms = 100 microseconds.

SLIDE 32: Network Core: Packet Switching – Store-and-Forward
================================================================================

COMPUTER NETWORKS: Store-and-Forward Packet Switching

Concept:
• Store-and-Forward Transmission:
  The packet switch must receive the ENTIRE packet before it can begin to transmit the first bit of the packet onto the outbound link.

Architecture Diagram:
  Source Host                    Router                    Destination Host
    [ Host ] -----------------> [ Router ] -----------------> [ Host ]
               Link rate R                 Link rate R
              Packet size L               Packet size L

Timing & Delay Analysis:
• Step 1: Source transmits entire L-bit packet to Router at rate R.
  - Transmission time = L/R seconds.
• Step 2: Router receives all L bits, inspects header, and transmits onto outgoing link at rate R.
  - Transmission time = L/R seconds.
• End-to-End Transmission Delay (ignoring propagation and processing delays):
  
  Total Delay = 2 * (L / R)

Pipelining with Multiple Packets:
• If source sends 3 packets back-to-back:
  - Time 0: Packet 1 begins transmission from Source.
  - Time L/R: Packet 1 arrives at Router; Router starts transmitting Packet 1 to Dest; Source starts transmitting Packet 2 to Router.
  - Time 2*(L/R): Packet 1 received at Dest; Packet 2 arrives at Router; Router starts transmitting Packet 2; Source transmits Packet 3.
  - Time 3*(L/R): Packet 2 received at Dest; Packet 3 arrives at Router; Router starts transmitting Packet 3.
  - Time 4*(L/R): Packet 3 received at Dest.
• Total time for N packets over 1 router (2 hops) = (N + 1) * (L / R).

SLIDE 33: Network Core: Queuing Delay & Packet Loss
================================================================================

COMPUTER NETWORKS: Packet Switching – Queuing Delay & Loss

Router Buffers (Queues):
• For each attached link, the router has an output buffer (output queue).
• If the arrival rate of packets to the link temporarily exceeds the link transmission rate (capacity):
  - Packets cannot be transmitted immediately and must wait in line inside the buffer.
  - This waiting time is called QUEUING DELAY.

Packet Loss (Drop):
• Router buffers have a FINITE capacity.
• If a packet arrives when the buffer is completely full:
  - There is no physical memory left to hold the packet.
  - The packet is DROPPED (PACKET LOSS).

SLIDE 34: Network Core: Two Key Functions – Routing vs. Forwarding
================================================================================

COMPUTER NETWORKS: Two Key Network-Core Functions

Every packet switch/router performs two distinct, fundamental operations:

1. FORWARDING (Data Plane - Local Action):
   • Moving packets from a router's incoming input port to the appropriate outgoing output port.
   • Takes place in hardware in nanoseconds / microseconds.
   • Uses a local FORWARDING TABLE: looks up packet destination address to find outbound interface.

2. ROUTING (Control Plane - Global Action):
   • Determining the end-to-end path (route) taken by packets from source to destination across the entire network.
   • Uses ROUTING ALGORITHMS (e.g., OSPF, BGP, RIP, Dijkstra, Distance Vector) to compute paths and populate local forwarding tables.
   • Takes place in software over seconds / milliseconds.

Analogy:
• Routing is like planning the trip from New York to Los Angeles using a map.
• Forwarding is like taking a specific exit ramp when driving through an interchange.

SLIDE 35: Network Core: Circuit Switching
================================================================================

COMPUTER NETWORKS: Circuit Switching

Principles:
• Dedicated Resources: The resources (buffers, link transmission rate) needed along a path between sender and receiver are RESERVED for the duration of the communication session.
• Guaranteed Performance: Since capacity is dedicated, transmission rate is guaranteed and there is NO queuing delay or congestion once the call is established.
• Traditional Domain: Traditional telephone networks (PSTN - Public Switched Telephone Network).

Call Setup Phase:
• Before any data can be transferred, an end-to-end connection (circuit) must be established across all intermediate switches.
• Requires call setup signaling messages.

Idle Waste:
• If the dedicated circuit is not in use (e.g., people listening or silent), the reserved bandwidth sits IDLE and cannot be used by other callers.

Circuit Switch Architecture Diagram:

            Reserved Circuit                 Reserved Circuit
          (Dedicated Bandwidth)            (Dedicated Bandwidth)

SLIDE 36: Multiplexing in Circuit-Switched Networks: FDM vs. TDM
================================================================================

COMPUTER NETWORKS: Circuit Multiplexing – FDM vs. TDM

How a shared physical link is divided into distinct circuits:

1. Frequency Division Multiplexing (FDM):
   • The link spectrum is divided into dedicated frequency bands.
   • Each call is allocated a unique frequency band for the entire duration of the connection.
   • Each user transmits continuously, but only within their narrow frequency slice.
   • Analogy: Traditional FM radio stations (each station broadcasts on its own frequency, e.g., 91.1 MHz).

2. Time Division Multiplexing (TDM):
   • Time is divided into recurring discrete time frames, and each frame is divided into a fixed number of TIME SLOTS.
   • Each call is assigned a periodic time slot within every frame.
   • During its assigned slot, the user gets the FULL bandwidth of the link.
   • When the slot ends, the user must wait until the next frame.

FDM vs. TDM Visual Representation:

     ^
     |  +-----------------+           +----+----+----+----+

     |  +-----------------+           +----+----+----+----+
     |  | Channel 3 (Call)|           | C1 | C2 | C3 | C4 | Frame 2
     |  +-----------------+           +----+----+----+----+
     |  | Channel 2 (Call)|           Time Slots (TDM)
     |  +-----------------+           Each user transmits at full
     |  | Channel 1 (Call)|           rate during their slot.
     |  +-----------------+

SLIDE 37: Why Packet Switching Won: Statistical Multiplexing
================================================================================

COMPUTER NETWORKS: Statistical Multiplexing

The Economic & Engineering Rationale:
• Circuit switching reserves a fixed slice of bandwidth for the entire call — even during silence.
• In a typical human voice call, 50% to 60% of the time is silence (listening, pauses). In computer data traffic, activity is even more bursty (users click a link, then read for minutes).
• Dedicated circuits waste massive amounts of idle capacity.
• Packet Switching allows many bursty users to share a single link dynamically:
  - Bandwidth is consumed ONLY when someone actually transmits a packet.
  - This is called STATISTICAL MULTIPLEXING: packets from multiple uncoordinated sources interleave on demand according to statistical probabilities.

Worked Example Comparison:
• Setup:
  - Shared Link Capacity = 1 Gbps (1,000 Mbps).
  - Each user needs: 1 Mbps when actively transmitting.
  - Users are active only 10% of the time (p = 0.1).

1. Circuit Switching:
   - Each user MUST be allocated a dedicated 1 Mbps slot.
   - Maximum Users Supported = 1,000 Mbps / 1 Mbps = 1,000 users MAXIMUM (fixed, hard limit).

2. Packet Switching:
   - Supports 5,000+ users!
   - Probability that more than 1,000 users are active simultaneously out of 5,000 with p = 0.1 is less than 10^-10 (virtually zero).
   - Hence, packet switching supports 5x to 10x more users with almost no noticeable blocking.

SLIDE 38: Packet Switching vs. Circuit Switching: Tradeoffs
================================================================================

COMPUTER NETWORKS: Packet vs. Circuit Switching Tradeoffs

Is Packet Switching a "Slam Dunk Winner"?
Advantages of Packet Switching:
• Ideal for bursty data: Users share bandwidth dynamically.
• Simpler management: No complex call setup / teardown state maintained in core routers.
• Maximum resource utilization: Idle users consume zero capacity.

Disadvantages of Packet Switching:
• Excessive congestion is possible: Packet delay and packet loss occur when buffer overflows.
• No hard performance guarantees: Quality of Service (QoS) requires additional protocols for real-time audio/video.
• Variable latency (jitter).

Human Analogies:
• Circuit Switching: Reserving a private restaurant table or private toll lane. Guaranteed, but if you don't show up or sit idle, it is completely wasted.
• Packet Switching: Rush-hour public highway or cafeteria line. Highly efficient, but during peak traffic jams, you must wait in line.

SLIDE 52: Performance: How Packet Delay and Loss Occur
================================================================================

COMPUTER NETWORKS: Sources of Packet Delay and Loss

Mechanism:
1. Packets arrive at router input ports.
2. If packets arrive faster than the outgoing link can transmit them:
   - Packets queue in router buffers, waiting their turn.
   - Each queued packet experiences QUEUING DELAY.
3. If the buffer is completely filled when a packet arrives:
   - The router has no space to store the arriving packet.
   - The packet is dropped, resulting in PACKET LOSS.

Delay & Loss Components at Router Node:
  [Arriving Packets] =====> [ Router Buffer ] =====> [ Link Transmitter ] =====> [ Physical Wire ]
                                  |                         |                           |
                            Queuing Delay           Transmission Delay          Propagation Delay
                            (or Packet Loss          (L / R)                     (d / s)
                             if full)

SLIDE 53: Performance: 4 Sources of Packet Delay (Overview & Formula)
================================================================================

COMPUTER NETWORKS: The 4 Sources of Packet Delay

Total Nodal Delay Equation:
  d_nodal = d_proc + d_queue + d_trans + d_prop

1. Nodal Processing Delay (d_proc):
   • Time required to examine the packet's header and determine where to direct the packet.
   • Includes checking for bit-level errors in packet header.
   • Typical magnitude: Typically microseconds (< 10 microseconds) or less.

2. Queuing Delay (d_queue):
   • Time the packet spends waiting in the buffer queue to be transmitted onto the link.
   • Depends on router congestion level and preceding traffic.
   • Typical magnitude: Microseconds to hundreds of milliseconds.

SLIDE 54: Performance: Transmission vs. Propagation Delay
================================================================================

COMPUTER NETWORKS: Transmission Delay vs. Propagation Delay Definitions

3. Transmission Delay (d_trans):
   • Time required to push ALL of the packet's bits into the link.
   • Formula:
     
                  L (Packet length in bits)
     d_trans  =  ----------------------------
                  R (Link transmission rate, bps)

4. Propagation Delay (d_prop):
   • Time it takes for a single bit to propagate from the beginning of the link to the next router.
   • Formula:
     
                  d (Length of physical link, meters)
     d_prop   =  -------------------------------------
                  s (Propagation speed of medium, m/s)

   • Speed of light in copper/fiber: s ≈ 2 * 10^8 m/sec (about 2/3 speed of light in vacuum).

CRITICAL DISTINCTION:
• d_trans is a function of PACKET LENGTH and LINK SPEED (nothing to do with distance).
• d_prop is a function of PHYSICAL DISTANCE and PROPAGATION SPEED (nothing to do with packet size or link speed).

SLIDE 56: Caravan Analogy: Scenario 1 (Slow Toll Booth, Fast Highway)
================================================================================

COMPUTER NETWORKS: Delay Analogy – Caravan Scenario 1

Analogy Setup:
• 10-car caravan (represents a 10-bit packet).
• Toll booth services 1 car every 12 seconds (bit transmission time = 12 sec).
• Toll booth ~ Router; Car ~ Bit; Caravan ~ Packet.
• Cars propagate down highway at 100 km/hr (propagation speed).
• Highway distance between Toll Booth 1 and Toll Booth 2 = 100 km.

Question: How long until the entire caravan is lined up before the 2nd toll booth?

Step-by-Step Solution:
1. Time to push entire caravan through Toll Booth 1:
   Time = 10 cars * 12 seconds/car = 120 seconds = 2 minutes (Transmission delay).
2. Time for the LAST car to propagate from Toll Booth 1 to Toll Booth 2:
   Time = Distance / Speed = 100 km / (100 km/hr) = 1 hour = 60 minutes (Propagation delay).
3. Total Time = 2 minutes + 60 minutes = 62 minutes.

SLIDE 57: Caravan Analogy: Scenario 2 (Fast Toll Booth, Superfast Cars)
================================================================================

COMPUTER NETWORKS: Delay Analogy – Caravan Scenario 2

New Parameters:
• Toll booth services 1 car every 1 minute (60 seconds).
• Cars travel at 1,000 km/hr.
• Distance = 100 km.

Question: Will cars begin arriving at the 2nd toll booth BEFORE all cars are serviced at the 1st toll booth?

Step-by-Step Solution:
1. Time for 1st car to clear Toll Booth 1 = 1 minute.
2. Travel time for 1st car = 100 km / (1,000 km/hr) = 0.1 hr = 6 minutes.
3. Total time for 1st car to reach Toll Booth 2 = 1 min + 6 min = 7 minutes.
4. But servicing all 10 cars at Toll Booth 1 takes 10 * 1 min = 10 minutes!
5. Answer: YES! At minute 7, the 1st car has already arrived at Toll Booth 2, while 3 cars are still waiting in line to be serviced at Toll Booth 1!

SLIDE 58: "Which Delay Wins?" (Numerical Comparison)
================================================================================

COMPUTER NETWORKS: Dominant Delay Analysis

Scenario: Downloading a 5 Megabyte (MB) image.
  File size = 5 MB = 5 * 10^6 bytes = 40 * 10^6 bits.

Scenario A: Fast 1 Gbps fiber link across 12,000 km (Intercontinental):
• Distance d = 12,000 km = 12,000,000 m. Speed s ≈ 2 * 10^8 m/s.
• Propagation Delay:
  d_prop = 12,000,000 / (2 * 10^8) = 0.06 s = 60 ms.
• Transmission Delay (R = 1 Gbps = 10^9 bps):
  d_trans = (5 * 10^6 * 8) / 10^9 = 40 * 10^6 / 10^9 = 0.04 s = 40 ms.
• Conclusion: Propagation delay dominates (60 ms > 40 ms).

Scenario B: Slow 1 Mbps link next door (Distance d ≈ 0):
• Distance is tiny, so d_prop ≈ 0.
• Transmission Delay (R = 1 Mbps = 10^6 bps):
  d_trans = (5 * 10^6 * 8) / 10^6 = 40 seconds!
• Conclusion: Transmission delay overwhelmingly dominates (40 seconds vs. microseconds).

SLIDE 59: Queuing Delay Revisited: Traffic Intensity
================================================================================

COMPUTER NETWORKS: Queuing Delay Dynamics

Parameters:
• R: Link transmission rate / bandwidth (bits/sec).
• L: Packet length (bits).
• a: Average packet arrival rate (packets/second).
• L * a: Average rate at which bits arrive at the queue (bits/sec).
• R: Rate at which bits are transmitted / serviced (bits/sec).

Traffic Intensity Metric (I):
  
                 L * a      (Bit Arrival Rate)
  Intensity I = -------  = --------------------
                   R        (Bit Service Rate)

Impact on Queuing Delay:
• I ≈ 0: Arriving traffic is very light; packets rarely wait; average queuing delay is close to zero.
• I -> 1: Traffic arrival approaches link capacity; queues build up; delay increases non-linearly.
• I > 1: More work arrives than can be serviced; queue grows indefinitely without bound; average delay is INFINITE (buffer overflows and packet loss occur).
• Gold Standard: Design network links such that Traffic Intensity I <= 0.7 to 0.8.

================================================================================
SLIDE 60: Queuing Delay Formula & Curve
================================================================================

COMPUTER NETWORKS: Traffic Intensity Formula & Exponential Growth

Theoretical Queuing Delay Estimation Formula (M/M/1 Queue approximation):
  
                I * L
  d_queue = -------------    (for I < 1)
              R * (1 - I)

Where:
• I = L * a / R (Traffic Intensity)
• L = Packet length (bits)
• R = Link capacity (bps)

Queue Delay Behavior:
  Average Delay
      ^
      |                                              | (Asymptote at I = 1)
      |                                             /
      |                                            /
      |                                           /
      |                                          /
      |                                        /
      |                                     .-'
      |                            _..---''
      +---------------------------+------------------> Traffic Intensity (La/R)
      0                          0.5               1.0
  (Small delay)            (Moderate delay)   (Explodes to Infinity)

SLIDE 61: Queuing Delay Formula: Why It Blows Up Near I = 1
================================================================================

COMPUTER NETWORKS: Queuing Delay Mathematical Analysis

Formula Regrouping:
  d_queue = (I * L) / (R * (1 - I))  for I < 1
  d_queue = (L / R) * [ I / (1 - I) ] = d_trans * [ I / (1 - I) ]

Key Insights:
• L/R is exactly the transmission delay (d_trans).
• Therefore, queuing delay is simply the transmission delay scaled by a CONGESTION MULTIPLIER:
  Multiplier = I / (1 - I)
• The congestion multiplier depends ONLY on traffic intensity (I = La/R), not directly on packet size or link rate.

Congestion Multiplier Table:
+-------------------+--------------------+---------------------------------------------+
| Traffic Intensity | Congestion Mult.   | Physical Meaning                            |
| I = (La / R)      | [ I / (1 - I) ]    |                                             |
+-------------------+--------------------+---------------------------------------------+
| 0.00              | 0x                 | No waiting at all                           |
| 0.50              | 1x                 | Queuing delay = 1 transmission time         |
| 0.80              | 4x                 | Queuing delay = 4 transmission times        |
| 0.90              | 9x                 | Queuing delay = 9 transmission times        |
| 0.99              | 99x                | Queuing delay = 99 transmission times       |
| -> 1.00           | -> Infinity        | Delay blows up indefinitely (buffer overflow)|
+-------------------+--------------------+---------------------------------------------+

Worked Numerical Example:
• Link capacity R = 10 Mbps = 10^7 bps.
• Packet length L = 1,000 bits.
• Base transmission delay d_trans = L / R = 1,000 / 10,000,000 = 100 microseconds (µs).
• Case 1: Low traffic arrival rate a = 1,000 packets/sec
  - Intensity I = (1,000 * 1,000) / 10,000,000 = 0.1
  - d_queue = 100 µs * [ 0.1 / (1 - 0.1) ] = 100 µs * (0.1 / 0.9) ≈ 11.1 µs.
• Case 2: High traffic arrival rate a = 9,000 packets/sec (9x increase)
  - Intensity I = (1,000 * 9,000) / 10,000,000 = 0.9
  - d_queue = 100 µs * [ 0.9 / (1 - 0.9) ] = 100 µs * (0.9 / 0.1) = 900 µs.
• Takeaway: A 9x increase in traffic arrival produced an 81x increase in queuing delay!

SLIDE 62: "Real" Internet Delays and Routes: Traceroute Mechanism
================================================================================

COMPUTER NETWORKS: Traceroute Principles

What do "real" Internet delay & loss look like?
• The `traceroute` program provides delay measurements from source to every intermediate router along the end-to-end Internet path towards a destination.

Operational Mechanism:
• For each hop distance i = 1, 2, 3, ...:
  - Source sends three probe packets towards destination with IP Time-To-Live (TTL) field set to i.
  - When the i-th router on the path receives the packet, the TTL drops from 1 to 0.
  - The router discards the packet and returns an ICMP "Time-to-Live Exceeded" (Type 11) error message back to the source.
  - Source receives the ICMP reply and records the Round-Trip Time (RTT) interval between transmission and reply.
  - Sending 3 probes per hop provides three RTT samples to detect jitter and variance.

Diagram:
  Source                                Router 1        Router 2        Destination
    |                                      |               |                 |
    | --- Probe 1,2,3 (TTL=1) -----------> | (TTL expires) |                 |
    | <--- ICMP TTL Exceeded ------------- |               |                 |
    |                                                      |                 |
    | --- Probe 1,2,3 (TTL=2) ---------------------------> | (TTL expires)   |
    | <--- ICMP TTL Exceeded ----------------------------- |                 |

SLIDE 64: How Traceroute Works (RFC Reference & Caveats)

Technical Specifications:
• Refer to RFC 1393: "Traceroute Using an IP Option".
• Linux/Unix traceroute traditionally uses UDP packets directed to high, unused destination ports (e.g., 33434+).
• Windows `tracert` uses ICMP Echo Request packets directly.
• When UDP probe reaches final destination host, the destination returns an ICMP "Port Unreachable" (Type 3, Code 3) error, terminating the trace.

"Don't Trust Traceroute Completely":
• Why delays can appear inconsistent:
  - Reverse path asymmetry: Packets return on a completely different physical path than they were sent.
  - Priority handling: Routers process ICMP generation at low CPU priority compared to hardware-switched data packets.
  - MPLS tunnels: Virtual circuits inside carrier backbones may hide internal hops.

SLIDE 65: Performance: Packet Loss Dynamics
================================================================================

COMPUTER NETWORKS: Packet Loss Mechanisms

How Packet Loss Occurs:
• Queues (buffers) preceding links in routers have FINITE memory capacity.
• When packets arrive at an already full queue, the arriving packet is DROPPED (LOST).

What Happens to Lost Packets?
• The lost packet may be:
  1. Retransmitted by previous node (rare in IP core; used in some link-layer protocols like WiFi).
  2. Retransmitted by source end system (via transport layer protocol like TCP).
  3. Not retransmitted at all (when using UDP; e.g., real-time voice/video streaming where old packets are useless).

Diagram:
                     Router Output Buffer
                 +---------------------------+
  Incoming       | [P5] | [P4] | [P3] | [P2] | =====> [Transmitting P1] ===> Link
  Packets =====> +---------------------------+
                     ^
                     |--- Arriving packet [P6] finds buffer FULL!
                          [P6] is DROPPED (Packet Loss)

SLIDE 66: Performance: Throughput Fundamentals
================================================================================

COMPUTER NETWORKS: Throughput Definitions & Fluid Pipe Model

Definition:
• Throughput: The rate (measured in bits per second, bps) at which bits are actually delivered from sender to receiver.
  - Instantaneous Throughput: Rate at any given instantaneous moment in time.
  - Average Throughput: Rate measured over an extended period of time (Total bits delivered / Total elapsed time).

Fluid Analogy (Pipes & Valves):
• Think of bits as fluid flowing through pipes of different widths.
• Server pumps fluid at rate Rs bits/sec into a pipe of capacity Rs.
• Pipe connects to a second pipe with capacity Rc bits/sec delivering fluid to client.

Diagram:
  [Server] =====(Pipe: Rs bits/sec)=====> [Router] =====(Pipe: Rc bits/sec)=====> [Client]

SLIDE 67: Bottleneck Link Analysis
================================================================================

COMPUTER NETWORKS: Bottleneck Link

The Bottleneck Principle:
• The BOTTLENECK LINK is the link on the end-to-end path that constrains (limits) the end-to-end throughput.

Two Primary Scenarios:
1. Scenario 1 (Rs < Rc):
   - Server link is narrower than client access link.
   - Fluid can only flow as fast as the server can pump it.
   - Average End-to-End Throughput = Rs bits/sec.

2. Scenario 2 (Rs > Rc):
   - Server link is wide, but client access link is narrow.
   - Packets queue before the client link; throughput is constrained by Rc.
   - Average End-to-End Throughput = Rc bits/sec.

General Rule for 2-hop path:
  Throughput = min(Rs, Rc)

SLIDE 68: Throughput: Numerical Example
================================================================================

COMPUTER NETWORKS: Throughput Calculation Example

Problem Statement:
• File size F = 32 million bits (32 Mbits).
• Server transmission rate Rs = 2 Mbps.
• Client access link rate Rc = 1 Mbps.
• What is the time needed to transfer the file?

Step-by-Step Solution:
1. Find the bottleneck transfer rate:
   Transfer Rate = min(Rs, Rc) = min(2 Mbps, 1 Mbps) = 1 Mbps = 1,000,000 bps.
2. Calculate total transfer time:
   Time = File Size / Transfer Rate
   Time = (32 * 10^6 bits) / (1 * 10^6 bits/sec)
   Time = 32 seconds!

If Rs were 100 Mbps and Rc were 10 Mbps:
• Rate = min(100, 10) = 10 Mbps.
• Time = 32 / 10 = 3.2 seconds.

SLIDE 69: Throughput in a Shared Network Scenario
================================================================================

COMPUTER NETWORKS: Shared Backbone Bottleneck

Scenario Setup:
• 10 independent servers download files to 10 independent clients simultaneously.
• Each server has access link Rs.
• Each client has access link Rc.
• All 10 connections share a common backbone link of capacity R bits/sec.
• The shared backbone link divides its transmission capacity equally among the 10 active connections.

General Formula:
  Throughput per connection = min(Rs, Rc, R / 10)

Worked Example:
• Rs = 2 Mbps
• Rc = 1 Mbps
• Shared backbone capacity R = 5 Mbps
• Fair share of backbone link per connection = R / 10 = 5 Mbps / 10 = 0.5 Mbps = 500 kbps.
• Bottleneck evaluation:
  min(Rs, Rc, R/10) = min(2 Mbps, 1 Mbps, 0.5 Mbps) = 0.5 Mbps (500 kbps).
• Result: The shared backbone link is the bottleneck; each client gets 500 kbps throughput.
