3.4 Principles of Reliable Data Transfer¶

3.4.1 Building a Reliable Data Transfer Protocol¶

Problem: Underlying channel can lose, corrupt, duplicate, reorder packets Goal: Provide reliable, in-order delivery to application

Approach: ACK/NAK + Retransmission + Sequence Numbers

rdt 1.0: Reliable channel¶

  • No errors, no loss
  • Simple: send, receive, deliver

rdt 2.0: Channel with bit errors¶

  • Add checksum for error detection
  • ACK (positive acknowledgment) / NAK (negative acknowledgment)
  • Retransmission on NAK or corrupted ACK/NAK
  • Sequence numbers (0/1) to detect duplicates

rdt 2.1: Sender handles corrupted ACK/NAK¶

  • Add sequence number to ACK/NAK
  • Sender retransmits if ACK/NAK corrupted

rdt 2.2: NAK-free (only ACKs)¶

  • Receiver sends ACK for last correctly received packet
  • Sender retransmits on timeout if no ACK
  • Duplicate ACKs trigger retransmission

rdt 3.0: Channel with loss AND errors¶

  • Timer for each packet
  • Timeout → retransmit
  • Problem: How to set timeout? (covered in 3.5.3)

3.4.2 Pipelined Reliable Data Transfer Protocols¶

Stop-and-Wait: Send one packet, wait for ACK → low utilization Utilization: U = (L/R) / (RTT + L/R)

Pipelining: Send multiple packets before waiting for ACKs - Increases utilization - Requires: larger sequence number space, buffering at sender/receiver

Two main approaches: 1. Go-Back-N (GBN) 2. Selective Repeat (SR)

3.4.3 Go-Back-N (GBN)¶

Sender Window: Size N, sequence numbers [base, base+N-1] - base = oldest unACKed packet - nextseqnum = next packet to send

Sender Behavior: - On data from app: if window not full, send packet, start timer if first in window - On ACK: cumulative ACK (ACK n = all up to n received); slide window - On timeout: retransmit ALL packets from base to nextseqnum-1

Receiver Behavior: - Only accepts in-order packets - Sends ACK for highest in-order packet received - Discards out-of-order packets (sends duplicate ACK)

Window Size Constraint: N ≤ 2ᵏ - 1 (k = sequence number bits) - Prevents ambiguity between old and new packets

Utilization: U = N × (L/R) / (RTT + L/R) (if N < N_optimal)

Example (N=10, every 5th packet lost): - Round 1: Send 1-10, lose 5,10 → ACK 4, timeout → 18 total transmissions

3.4.4 Selective Repeat (SR)¶

Sender Window: Size N, per-packet timers - Only retransmits specific timed-out packet

Receiver Window: Size N, buffers out-of-order packets - Accepts packets in [rcv_base, rcv_base+N-1] - Sends individual ACK for each packet - Delivers in-order to application when possible

Window Size Constraint: N ≤ 2ᵏ⁻¹ (Proof: 2N ≤ 2ᵏ → N ≤ 2ᵏ⁻¹) - Prevents overlap between sender and receiver windows

Utilization: Same as GBN but fewer retransmissions

Example (same conditions): 12 total transmissions (only retransmit lost packets)
