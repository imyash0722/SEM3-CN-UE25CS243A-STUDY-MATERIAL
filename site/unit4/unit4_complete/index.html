✅ Study Checklist (ISA-2)¶

Link Layer Fundamentals¶

  • Services: framing, link access, MAC addressing (48-bit), reliable delivery (rare on wired), error detection/correction, flow control
  • Implementation: NIC or on-chip, hardware/software/firmware
  • Encapsulation: datagram → frame (header + trailer)

Error Detection & Correction¶

  • Single-bit parity: even parity, detects odd flips only
  • 2D parity: row + column, detects AND corrects single-bit errors
  • Internet checksum: 1's complement sum of 16-bit words, weak (misses compensating errors)
  • CRC: D×2ʳ mod G, detects all burst errors < r+1 bits, Ethernet uses CRC-32

Multiple Access Protocols¶

  • Channel partitioning: TDMA (time slots), FDMA (frequency), CDMA (codes)
  • Random access: ALOHA, slotted ALOHA, CSMA, CSMA/CD, CSMA/CA
  • CSMA/CD (Ethernet): listen before transmit, detect collision → abort, binary exponential backoff (K ∈ {0..2ⁿ⁻¹}, wait K×512 bit times)
  • CSMA/CA (WiFi): DIFS → random backoff → transmit → wait ACK → retry on failure
  • Why no CD in modern Ethernet: switched full-duplex = dedicated channels = no collisions
  • WiFi still shared → CSMA/CA with RTS/CTS for hidden terminal

Ethernet & Switches¶

  • Frame: preamble (8B) | dst MAC (6B) | src MAC (6B) | type (2B) | data (46-1500B) | CRC (4B)
  • Min frame: 64 bytes (512 bits = collision budget), Max: 1518 bytes
  • Unreliable, connectionless: no ACKs, dropped frames recovered by TCP
  • Switch: self-learning (src MAC → port on arrival), flooding if dest unknown, forwarding table with TTL (~60s)
  • Hub vs Switch: hub = 1 collision domain, switch = per-port collision domain (full duplex)

VLANs¶

  • 802.1Q tag: 4 bytes after src MAC (TPID=0x8100, priority 3b, DEI 1b, VLAN ID 12b = 4094 usable)
  • Access port: 1 VLAN, untagged frames to/from device
  • Trunk port: multiple VLANs, tagged frames
  • Native VLAN: 1 VLAN crosses trunk untagged, both ends must agree
  • VLAN-aware forwarding: lookup (VLAN, dest MAC), flood only within VLAN + trunks
  • Inter-VLAN routing: router or L3 switch, each VLAN = separate IP subnet

ARP¶

  • Broadcast query "Who has IP X? Tell IP Y" → unicast reply "IP X is at MAC Z"
  • ARP table: IP/MAC mappings with TTL (minutes)
  • Both requester and responder update their tables

Physical Layer¶

  • Encoding: NRZ (low=0, high=1), Manchester (transition=bit, self-clocking), 4B/5B (100 Mbps), 8B/10B (Gbps)
  • Media: twisted pair (Cat5e 1G, Cat6 10G, 100m), coax (cable TV), fiber (SMF/MMF, km, immune EMI), wireless (radio, half-duplex)

Wireless LANs (802.11)¶

  • BSS: hosts + AP; ESS: multiple BSSs + distribution system
  • Channels: 2.4 GHz (11), 5 GHz, 6 GHz (WiFi 6E)
  • Association: scan → select AP → authenticate → DHCP
  • CSMA/CA: DIFS → random backoff → transmit → SIFS → ACK
  • RTS/CTS: reserve channel, solve hidden terminal
  • Hidden terminal: A and C can't hear each other, both transmit to B → collision
  • Exposed terminal: C hears B → defers unnecessarily
  • Standards: 802.11b (11M), g (54M), n (600M), ac (3.47G), ax (14G), be (46G)

Unit 4: Link Layer and LAN (Chapter 6)¶

Overview¶

This unit covers Chapter 6 of Kurose & Ross (9th Edition): The Link Layer and LANs

Course Hours: 14 hours

6.1 Introduction to Link Layer¶

Terminology¶

  • Nodes: Hosts, routers, switches, WiFi access points
  • Links: Communication channels connecting adjacent nodes
  • Wired (copper, fiber)
  • Wireless (radio)
  • Frame: Layer-2 packet, encapsulates datagram

Link Layer Responsibility¶

Transfer datagram from one node to physically adjacent node over a link

Link Layer Services¶

Service Description
Framing Encapsulate datagram into frame, add header/trailer
Link Access Channel access if shared medium (MAC protocol)
MAC Addressing 48-bit MAC addresses in frame headers identify source/destination
Reliable Delivery Between adjacent nodes (rarely used on wired; wireless: high error rates)
Error Detection Detect errors from signal attenuation, noise
Error Correction Identify and correct bit errors without retransmission
Flow Control Pacing between adjacent sending/receiving nodes
Half/Full Duplex Half: one direction at a time; Full: simultaneous both directions

Where is Link Layer Implemented?¶

  • In each host: Network Interface Card (NIC) or on-chip
  • Implements link + physical layer
  • Combination of hardware, software, firmware
  • Attaches via host bus (PCI/PCIe)

6.2 Error Detection and Correction¶

Error Detection Framework¶

  • EDC: Error detection and correction bits (redundancy)
  • D: Data protected by error checking
  • Receiver computes EDC on received D', compares with received EDC'
  • Not 100% reliable: Larger EDC field → better detection/correction

Parity Checking¶

Single bit parity (even parity): - Set parity bit so total number of 1's is even - Detects single bit errors - Cannot detect: Even number of bit flips

Two-dimensional bit parity: - Row parity + column parity - Detects AND corrects single bit errors - Intersection of row/column parity error = error location

Example (from slides): Send 1011 0110 with even-parity bit - Data has 5 ones → parity bit = 1 → 6 ones total (even) - Two bits flip → count changes by −2, 0, or +2 → still even → check passes - Answer: No error detected (parity misses even number of flips)

Internet Checksum (UDP/TCP)¶

Sender: 1. Treat segment (header + data + pseudo-header) as sequence of 16-bit integers 2. Compute 1's complement sum 3. Put checksum in checksum field

Receiver: 1. Compute 1's complement sum of received segment 2. If equals checksum field → no error detected 3. If not equal → error detected

Cyclic Redundancy Check (CRC)¶

More powerful error-detection coding - D: Data bits (binary number) - G: Generator polynomial (r+1 bits) - R: r CRC bits (remainder)

Goal: Compute R such that <D,R> exactly divisible by G (mod 2) - Receiver knows G, divides <D,R> by G - If non-zero remainder → error detected - Can detect all burst errors < r+1 bits - Widely used: Ethernet, 802.11 WiFi

CRC Calculation: 1. Append r zeros to data 2. Binary division by G 3. Remainder = CRC (r bits) 4. Transmit D followed by R

Common Generators: - CRC-32 (Ethernet): x³² + x²⁶ + x²³ + x²² + x¹⁶ + x¹² + x¹¹ + x¹⁰ + x⁸ + x⁷ + x⁵ + x⁴ + x² + x + 1

Numerical Example (from slides): - D = 101110, d = 6, G = 1001, r = 3 - Append 3 zeros: 101110000 - Divide by 1001: remainder = 101 - Transmitted: 101110101

Another Example: - Bit stream 1101011011, generator x⁴+x+1 = 10011 - Append 4 zeros, divide, remainder = CRC

6.3 Multiple Access Protocols¶

Two Types of Links¶

  1. Point-to-point: Ethernet switch to host, PPP, HDLC
  2. Broadcast (shared medium):
  3. Old-fashioned Ethernet (coax)
  4. Upstream HFC (cable)
  5. 802.11 WiFi, 4G/5G, satellite

Multiple Access Protocol¶

Distributed algorithm determining how nodes share channel - Communication about channel sharing must use channel itself - No out-of-band coordination channel

Ideal MAC Protocol¶

Given: MAC channel of rate R bps 1. When one node wants to transmit → sends at rate R 2. When M nodes want to transmit → each at average rate R/M 3. Fully decentralized: no special coordinator, no clock sync 4. Simple

MAC Protocol Taxonomy¶

  1. Channel Partitioning (TDMA, FDMA, CDMA)
  2. Divide channel into pieces (time slots, frequency, code)

  3. Allocate piece to node for exclusive use

  4. Random Access (ALOHA, Slotted ALOHA, CSMA, CSMA/CD, CSMA/CA)

  5. Channel not divided, allow collisions

  6. "Recover" from collisions

  7. Taking Turns (Polling, Token Passing)

  8. Nodes take turns; nodes with more data take longer turns

CSMA (Carrier Sense Multiple Access)¶

Simple CSMA: Listen before transmit - If channel sensed idle → transmit entire frame - If channel sensed busy → defer transmission

CSMA/CD: CSMA with Collision Detection - Collisions detected within short time - Colliding transmissions aborted (reduces wastage) - Easy in wired, difficult in wireless

CSMA Collisions¶

  • Propagation delay means two nodes may not hear each other's just-started transmission
  • Collision: entire packet transmission time wasted
  • Distance & propagation delay affect collision probability

Ethernet CSMA/CD Algorithm¶

  1. NIC receives datagram, creates frame
  2. If channel idle → start transmission; if busy → wait until idle
  3. If transmits entire frame without collision → done
  4. If detects collision while sending → abort, send jam signal
  5. Binary Exponential Backoff:
  6. After n collisions, choose K randomly from {0, 1, ..., 2ⁿ⁻¹}
  7. Wait K × 512 bit times, return to step 2
  8. More collisions → longer backoff

Is Collision Detection Still Used?¶

Modern Ethernet (Switched, Full-Duplex): - Switch gives each device dedicated cable/port - Each direction has own channel → no collisions - Collision detection switched OFF - Wi-Fi still shared: Everyone uses one radio channel → collisions happen (CSMA/CA)

6.4 Switched LANs¶

MAC Addresses¶

  • 32-bit IP address: Network-layer, used for L3 forwarding
  • 48-bit MAC address: Link-layer, used locally to get frame between physically-connected interfaces
  • Format: 6 bytes, hexadecimal (e.g., 1A-2F-BB-76-09-AD)
  • Burned in NIC ROM (usually unique); sometimes software-assigned (WiFi private addresses)

Analogy: MAC = Aadhar number; IP = Postal address Portability: MAC flat address → can move interface between LANs; IP depends on subnet

Private Wi-Fi Addresses¶

  • Factory address = same everywhere → tracking risk
  • Private address: invented per network (different at mall, airport, campus)
  • Second hex digit: 2, 6, A, E = locally assigned
  • Trade-off: Breaks sign-ins, fixed IP bookings, device allow-lists

ARP (Address Resolution Protocol)¶

Question: How to determine MAC address knowing IP address?

ARP Table: Each IP node (host, router) on LAN has table: - IP/MAC mappings: <IP address; MAC address; TTL> - TTL: Time after which mapping forgotten (typically minutes)

ARP Protocol in Action¶

Example: A wants to send to B, B's MAC not in A's ARP table 1. ARP Query: A broadcasts frame (dst MAC = FF-FF-FF-FF-FF-FF) containing "Who has B's IP? Tell A" 2. All nodes receive; only B (matching IP) replies 3. ARP Reply: B unicasts to A: "B's IP is at MAC" 4. A caches mapping in ARP table

Key points: - All nodes receive broadcast; only target replies - Both A and B update their ARP tables - ARP trusts replies → ARP spoofing possible

MCQ (from slides): A asks "who has B's IP?" in frame to FF-FF-FF-FF-FF-FF. Who receives/answers? - a) Only B receives, B answers → False - b) All nodes receive; only B answers to A → True - c) All receive, all answer → False - d) Only router receives → False

MCQ (from slides): After A asked, B answered. Whose ARP table has new entry? - a) Only A's → False - b) A's and B's (each other's) → True - c) Every node's → False - d) Only switch's → False

Routing to Another Subnet (IP + MAC Addressing Walkthrough)¶

Scenario: A (111.111.111.111) → B (222.222.222.222) via Router R

Key Principle: IP addresses stay same end-to-end; MAC addresses only get you to next hop

Step-by-step: 1. A compares subnet → B not on same LAN → send to default gateway R 2. A resolves R's MAC via ARP on left LAN 3. A creates IP datagram (src A, dst B), encapsulates in frame (src A, dst R) 4. R receives, strips frame, checks routing table → forward out right interface 5. R resolves B's MAC via ARP on right LAN 6. R re-encapsulates: new frame (src R-right, dst B), same IP datagram 7. B receives, extracts IP datagram, delivers to transport layer

Frame-by-frame sequence (from slides): | Step | Sender | Receiver | Message | Src MAC | Dst MAC | |------|--------|----------|---------|---------|---------| | 1 | A | - | Compare subnets (different) → send to R | - | - | | 2 | A | All left LAN | ARP Request: "Who has R? Tell A" | A | FF-FF-FF-FF-FF-FF | | 3 | R | A | ARP Reply: "R is at MAC_R" | MAC_R | A | | 4 | A | R | Data frame (IP: A→B, MAC: A→R) | A | MAC_R | | 5 | R | - | Strip frame, route to right interface | - | - | | 6 | R | All right LAN | ARP Request: "Who has B? Tell R" | MAC_R | FF-FF-FF-FF-FF-FF | | 7 | B | R | ARP Reply: "B is at MAC_B" | MAC_B | MAC_R | | 8 | R | B | Data frame (IP: A→B, MAC: R→B) | MAC_R | MAC_B |

6.5 Ethernet¶

Dominant Wired LAN Technology¶

  • First widely used LAN tech
  • Simpler, cheaper
  • Speed race: 10 Mbps → 800 Gbps (1.6 Tbps coming)
  • Single chip, multiple speeds

Ethernet Topology¶

Type Description
Bus (legacy) All nodes in same collision domain
Switched (modern) Active L2 switch in center; each spoke separate collision domain; full duplex

Hub vs Switch¶

  • Hub: Repeats every bit to every port → 1 collision domain
  • Switch: Each port own collision domain; full duplex → no collisions

MCQ (from slides): 8 PCs on hub, 8 on switch. How many collision domains? - a) Hub: 1; switch: 8 → True - b) Hub: 8; switch: 1 - c) Hub: 1; switch: 1 - d) Hub: 8; switch: 8

Ethernet Frame Structure¶

Preamble (8 bytes) | Dest MAC (6) | Src MAC (6) | Type (2) | Data (46-1500) | CRC (4)
- Preamble: 7 bytes 10101010 + 1 byte 10101011 (clock sync) - Addresses: Dest first (early filtering) - Type: Higher layer protocol (0x0800 = IP) - CRC: Cyclic redundancy check - Min frame: 64 bytes (512 bits = collision budget) - Max frame: 1518 bytes (1500 MTU + 18 header/CRC)

Smallest frame: 6+6+2+46+4 = 64 bytes Largest frame: 6+6+2+1500+4 = 1518 bytes

Ethernet: Unreliable, Connectionless¶

  • Connectionless: No handshaking between NICs
  • Unreliable: No ACKs/NAKs; dropped frames recovered only by higher layer (TCP)
  • MAC Protocol: Unslotted CSMA/CD with binary backoff (shared links)

MCQ (from slides): Frame fails CRC at second router. Who notices, who resends? - a) Second router asks first to resend → False - b) TCP at sender notices gap and resends → True - c) First router resends after timeout → False - d) Nobody: file arrives with hole → False

6.6 Ethernet Switches¶

Switch = Link-Layer Device¶

  • Stores and forwards Ethernet frames
  • Examines destination MAC, selectively forwards
  • Transparent: Hosts unaware of switches
  • Plug-and-play, Self-learning

Self-Learning¶

  • When frame received → "learn" sender location (incoming interface)
  • Record (MAC, interface) in switch table with timestamp (TTL ~60s)

Forwarding/Filtering¶

When frame received: 1. Record incoming link, sender MAC 2. Lookup destination MAC in table 3. If found: - If destination on same segment → drop - Else forward on indicated interface 4. If not found → flood (forward on all except arriving interface) 5. Broadcast frames (FF-FF-FF-FF-FF-FF) always flooded

Interconnecting Switches¶

  • Self-learning works across multiple switches
  • Switch learns which host reachable via which switch port

MCQ (from slides): C sends to I, I replies to C. Switch 2 learns C but not I. Why? - a) S4 knew C was toward S1, so I's reply skipped S2 → True - b) S2's table was full - c) S2 learns only from frames addressed to it - d) I's reply was broadcast

MCQ (from slides): Laptop sends ARP broadcast. Which devices receive it? - a) Only devices on laptop's own switch - b) Only router - c) Every device on every switch, up to router → True - d) Every device, including outside networks

6.7 VLANs (Virtual LANs)¶

Problem: Large Broadcast Domain¶

  • Traditional switched LAN = single broadcast domain
  • As LAN grows: broadcast traffic (ARP, DHCP, unknown MAC) reaches everyone
  • Scaling, security, privacy issues

What is a VLAN?¶

Method of dividing single physical switched network into multiple logical LANs - Devices in same VLAN communicate as if on same physical network - Even if connected to different switches/locations

VLAN Tag (802.1Q)¶

4-byte tag inserted after source MAC: 

Tag marker (0x8100) | Priority (3) | Drop (1) | VLAN ID (12 bits)
- Priority: 0-7 (voice = 5) - VLAN ID: 12 bits → 4,094 usable VLANs (0, 4095 reserved) - Frame grows from 1518 to 1522 bytes

Access vs Trunk Ports¶

Port Type Description
Access One VLAN only; frames untagged to/from device
Trunk Multiple VLANs; frames tagged
Native VLAN One VLAN crosses trunk untagged; both ends must agree

VLAN-Aware Switch Forwarding¶

  1. Note frame's VLAN (from port or tag)
  2. Learn: Record (VLAN, src MAC) → port
  3. Lookup (VLAN, dest MAC):
  4. Known: send on that port
  5. Unknown/broadcast: flood only to ports in same VLAN + trunks carrying it
  6. Tag/untag on output: add tag on trunk, remove on access

MCQ (from slides): PC on access port 5 (VLAN 20) sends broadcast. Ports 1-2 VLAN 10, 5-6 VLAN 20, 8 trunk (10,20). Where does broadcast go? - a) Every port (broadcasts ignore VLANs) - b) Port 6 untagged, port 8 tagged 20 → True - c) Only port 8 (trunk) tagged 20 - d) Only router

Inter-VLAN Routing¶

  • Each VLAN = separate IP network
  • Crossing VLANs = routing (L3)
  • Options: Router on trunk, or Layer-3 switch (switch + router in one)

6.8 A Day in the Life of a Web Request (Synthesis)¶

Scenario: Student on campus network requests www.google.com

Protocol Stack Journey¶

  1. DHCP: Get IP, gateway, DNS server
  2. ARP: Get gateway MAC
  3. DNS: Resolve www.google.com → IP
  4. TCP 3-way handshake: Establish connection
  5. HTTP Request/Response: Get web page
  6. Link Layer: Ethernet frames, switch forwarding, VLANs

Key insight: Every layer involved; encapsulation/decapsulation at each hop

6.9 Physical Layer¶

Purpose¶

Encode binary digits (frames) into signals to transmit/receive across physical media - Analog signal: Continuous-valued (amplitudes, frequencies) - Digital signal: Discrete-valued (0s & 1s) - Physical media: Copper, optical fiber, wireless

Physical Layer Elements¶

  1. Physical media & connectors
  2. Bit representation on media
  3. Encoding of data & control info
  4. Transmitter/receiver circuitry

Physical Layer Devices¶

  • Hub, Repeater, Modem, Cables, Network Adapters

Encoding Schemes¶

Encoding Description
NRZ Low voltage = 0, high voltage = 1
Manchester Low→high transition = 1; high→low = 0 (self-clocking)
4B/5B 4 data bits → 5 code bits (Ethernet 100 Mbps)
8B/10B 8 data bits → 10 code bits (Gigabit Ethernet)

Transmission Media¶

Media Characteristics
Twisted Pair (UTP/STP) Cat5e: 1 Gbps; Cat6: 10 Gbps; 100m max
Coaxial Cable Two concentric conductors; cable TV/HFC
Fiber Optic (SMF/MMF) Light pulses; 10s-100s Gbps; km distances; immune to EMI
Wireless Radio Electromagnetic spectrum; broadcast, half-duplex

6.10 Wireless LANs: IEEE 802.11¶

Wireless Network Context¶

  • More mobile subscribers than fixed (10:1)
  • More mobile broadband devices than fixed (5:1)
  • Two challenges: Wireless (comm over wireless link) + Mobility (changing attachment point)

Elements of Wireless Network¶

  • Wireless hosts: Laptop, smartphone, IoT (stationary or mobile)
  • Base station: Connected to wired network; relays between wired and wireless hosts (cell tower, AP)
  • Wireless link: Connects mobiles to base station; multiple access protocol coordinates access

Wireless Network Taxonomy¶

Single Hop Multiple Hops
Infrastructure Host → AP → Internet (WiFi, 4G/5G) Mesh: relay through wireless nodes
Ad Hoc No base station, no Internet (Bluetooth) MANET, VANET

IEEE 802.11 (WiFi) Architecture¶

  • BSS (Basic Service Set): Wireless hosts + Access Point (AP)
  • SSID: Service Set ID (network name)
  • Channels: 2.4 GHz (11 channels), 5 GHz, 6 GHz (WiFi 6E)
  • Association: Scan channels → select AP → authenticate → DHCP

802.11 Standards Evolution¶

Standard Year Max Rate Frequency Brand
802.11b 1999 11 Mbps 2.4 GHz WiFi 1
802.11g 2003 54 Mbps 2.4 GHz WiFi 3
802.11n 2009 600 Mbps 2.4/5 GHz WiFi 4
802.11ac 2013 3.47 Gbps 5 GHz WiFi 5
802.11ax 2020 14 Gbps 2.4/5/6 GHz WiFi 6/6E
802.11be 2024 46 Gbps 2.4/5/6/7 GHz WiFi 7

All use CSMA/CA for multiple access

CSMA/CA (Collision Avoidance)¶

Why not CSMA/CD?: Collision detection difficult in wireless (can't transmit and listen simultaneously on same frequency)

CSMA/CA Mechanism: 1. Listen (DIFS): If idle → wait random backoff, then transmit 2. RTS/CTS (optional): Reserve channel (hidden terminal problem) 3. ACK: Receiver sends ACK after successful frame 4. No ACK → assume collision/loss → backoff, retry

802.11 Frame Structure¶

  • Frame Control: Type (data, control, management), subtype
  • Duration/ID: NAV (Network Allocation Vector) for virtual carrier sense
  • Addresses: Up to 4 addresses (src, dst, BSSID, transmitter/receiver)
  • Sequence Control: Fragment number, sequence number
  • Frame Body: Payload
  • FCS: Frame Check Sequence (CRC-32)

Hidden/Exposed Terminal Problems¶

  • Hidden Terminal: A and C can't hear each other, both transmit to B → collision at B
  • Solution: RTS/CTS (Request to Send / Clear to Send)
  • Exposed Terminal: B transmitting to A, C hears B → C defers unnecessarily
  • C could transmit to D without interfering

Power Management¶

  • PSM (Power Save Mode): Client sleeps, wakes for beacon, tells AP it's awake
  • TIM (Traffic Indication Map): AP buffers frames for sleeping clients

Complete Questions, Examples, and MCQs from Slides and Textbook¶

Numerical Problems (Exam Practice)¶

Q1. Parity Check: Send 1011 0110 with even parity. Two bits flip. What does receiver conclude? - Data has 5 ones → parity = 1 (even total) - Two flips change count by ±2 or 0 → still even - Answer: No error detected

Q2. Two-Dimensional Parity: Given matrix with row/column parity, detect and correct single-bit error - Row parity error on row 3, column parity error on column 2 - Error at (3,2): flip bit

Q3. CRC Calculation: D = 101110, G = 1001 (r=3) - Append 3 zeros: 101110000 - Divide by 1001: remainder = 101 - Transmitted: 101110101

Q4. CRC Numerical: Bit stream 1101011011, generator x⁴+x+1 = 10011 - Append 4 zeros, divide by 10011 - Compute remainder → transmitted bit string

Q5. Ethernet Frame Size: Dest 6B, Src 6B, Type 2B, Data 46-1500B, CRC 4B - Min frame = 6+6+2+46+4 = 64 bytes - Max frame = 6+6+2+1500+4 = 1518 bytes - Preamble (8B) not counted

Q6. Binary Exponential Backoff: After 3 collisions - K ∈ {0, 1, ..., 2³⁻¹} = {0, 1, 2, 3, 4, 5, 6, 7} - Wait K × 512 bit times

Q7. VLAN Tag: 4 bytes after source MAC - TPID: 0x8100 - Priority: 3 bits (0-7) - Drop eligible: 1 bit - VLAN ID: 12 bits (4094 usable)

Review Questions¶

  1. Link layer services?

  2. Framing, link access, reliable delivery, error detection/correction, flow control

  3. Where is link layer implemented?

  4. NIC or on-chip; hardware/software/firmware

  5. Parity vs CRC?

  6. Parity: single bit, detects odd flips only

  7. CRC: polynomial division, detects all bursts < r+1 bits

  8. Internet checksum?

  9. 1's complement sum of 16-bit words; weak (misses compensating errors)

  10. CSMA/CD vs CSMA/CA?

  11. CD: detects collision, aborts (wired)

  12. CA: avoids collision, uses ACK/RTS/CTS (wireless)

  13. Why no collision detection in modern Ethernet?

  14. Switched full-duplex = dedicated channels = no collisions

  15. MAC vs IP address?

  16. MAC: 48-bit, flat, local delivery, portable

  17. IP: 32-bit, hierarchical, global routing, subnet-dependent

  18. ARP operation?

  19. Broadcast query "Who has IP X?" → unicast reply "X is at MAC Y"

  20. Switch self-learning?

  21. Learn src MAC → port on frame arrival; flood if dest unknown

  22. VLAN purpose?

    • Divide broadcast domain; security, scalability, privacy

  23. Access vs trunk port?

    • Access: 1 VLAN, untagged; Trunk: multiple VLANs, tagged

  24. Inter-VLAN routing?

    • Requires router or L3 switch; each VLAN = separate IP subnet

  25. 802.11 CSMA/CA?

    • Listen (DIFS), random backoff, transmit, wait ACK, retry on failure

  26. Hidden terminal problem?

    • A and C can't hear each other, both transmit to B
    • Solution: RTS/CTS reserves channel

  27. Physical layer encoding?

    • NRZ, Manchester, 4B/5B, 8B/10B for clock recovery, DC balance

Q12. Modern Ethernet - collision detection: - Switched OFF (full-duplex, no collisions)

Q20. ARP trusts replies → ARP spoofing possible

Q21. Routing to another subnet - key principle: - IP addresses stay same end-to-end; MAC addresses only get you to next hop
